创建团队并邀请同事，把自己的 Skill 共享到团队；成员取得经过校验的固定版本，再选择安装到本机 Agent。SkillHub 管理的个人钥匙与 Skill 文件分开，团队需要共用的钥匙须另外授权。

## 前提

双方安装 APP，登录同一实例的账号。共享的是自己的 Skill，先保存修改为版本；团队或商店取得的内容不能因此变成自己的作品再次共享，内置管理 Skill 也不能共享。

## 角色与范围

| 角色 | 权限 |
| --- | --- |
| 所有者 | 编辑团队、生成邀请、审批申请、移除成员、解散团队，也可共享与安装 |
| 成员 | 查看共享、安装、接收更新、共享自己的 Skill、讨论与退出 |

退出或移出后不能再通过团队读取内容；已经安装到本机的副本不会被远程删除。

## 共享步骤

1. 在「团队」新建团队，填写名称。
2. 所有者生成邀请链接，成员打开并登录后加入；过期后重新生成，也可审批加入申请。自部署先完成 [实例注册](../self-host/invite-members.md)。
3. 在「我的 Skills」选择自己的 Skill，执行「共享到团队」。
4. 核对预检。首次共享建立账号资产并上传固定版本；同编号内容不同需先保存新版本，不覆盖历史。
5. 成员在「团队共享」安装到本机，再安装到 Agent。作者保存并再次共享后，成员可更新到新固定版本；本地有修改时先处理。
6. 取消共享会停止后续团队访问，不删除成员已经安装的副本。

```sh
skillhub team list --json
skillhub team share preflight --local-skill-id "<local-skill-id>" --team-id "<team-uuid>" --json
skillhub team share apply --local-skill-id "<local-skill-id>" --team-id "<team-uuid>" --plan-digest "<planDigest>" --json
skillhub team share status --local-skill-id "<local-skill-id>" --team-id "<team-uuid>" --json
skillhub team updates --json
```

## 密钥与运行

个人钥匙由 SkillHub 单独保管，不进入打包、版本、共享或导出的文件。直接写进正文、脚本和 Skill 配置文件的秘密不受这条保证保护，分享前检查文件。

当前团队钥匙入口是「钥匙」页的团队页签：成员可以放入钥匙，持有人或负责人可撤销、排除具体 Skill 并查看使用记录。适用范围是已共享到该团队、声明该钥匙且未被排除的 Skill。旧指南逐 Skill「提供给团队」的操作已由该入口替代。

运行时用 `skillhub run <skill-id> -- <program> [args...]`，只把已声明且授权的值注入该子进程。值不输出到当前 Shell，但运行的程序已经能读到它，只运行可信程序。团队值通过加密存储与运行时权限校验取得，不因复制文件获得授权。

## 与公开商店的区别

| 项目 | 团队共享 | 公开商店 |
| --- | --- | --- |
| 可见范围 | 当前团队成员 | 公开浏览 |
| 流程 | 共享即生效 | 投稿审核通过后公开 |
| 版本 | 作者共享的固定版本 | 审核通过的固定版本 |
| 适用内容 | 内部流程、业务上下文 | 面向公众的通用 Skill |

原指南没有真实双账号团队全流程演示，本次迁入也不代表完成该验收。

## 常见问题

### 共享会把我的个人 Key 发出去吗

不会携带 SkillHub 独立管理的个人值；硬编码在文件里的秘密仍需自行移除。

### 同事需要共用 Key 怎么办

在「钥匙」的团队页签放入团队钥匙，按 Skill 授权范围使用；不要把它写入共享包。

### 退出团队会远程删除本机副本吗

不会，但后续团队读取和钥匙获取会重新检查成员资格。

### 可以直接转共享商店下载的 Skill 吗

不能通过下载获得作者权。按 [商店来源规则](marketplace.md) 使用。
