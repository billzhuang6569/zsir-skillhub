钥匙是 Skill 需要的 API Key、Token 等凭据。输出目录、模型选择等普通配置由 Skill 自己处理；SkillHub 不提供通用参数管理器。

## 个人钥匙

在「钥匙」页填写变量名和值；同一把可供多个 Skill 使用。可添加别名以匹配不同 Skill 声明的名字；同名多把使用标签区分，并保留一把默认值，也可为具体 Skill 指定某把。

个人值按空间、账号隔离，仅留本机，不随 Skill 包或账号同步。商店或团队来源首次读取个人钥匙时，在 APP 选择允许、仅这次或拒绝；仅这次授权在 10 分钟内供下一次运行消费。可关闭「以后不再询问」。

## 团队钥匙

团队任一有效成员可在团队页签放入或更换钥匙；持有人或负责人可撤销、排除指定 Skill、查看最近使用。共享到团队且声明该变量、没有被排除的 Skill 才在授权范围内。

持有人退出后钥匙留在团队；团队解散撤销全部团队钥匙。Skill 取消共享只移出使用范围，不撤销整个团队的钥匙。

## 运行时如何选择

显式选择优先；未显式选择时，先该 Skill 的个人覆盖值，再个人钥匙库，再唯一可用团队值。多个团队候选需要选择，没有值需要填写；显式选中的团队来源失效时不会悄悄回退。

```sh
skillhub env status --skill-id "<local-skill-id>" --json
skillhub run "<local-skill-id>" -- python scripts/main.py
```

第二条仅在该 Skill 确有相应脚本且当前目录正确时使用。只注入已声明、已授权的变量，不输出值；被运行程序可以读取其环境，只运行可信程序。

`MISSING_KEY` 表示缺值，`NEEDS_CHOICE` 表示需选来源，`NEEDS_CONSENT` 表示需在 APP 授权。CLI 不提供钥匙明文写入或授权命令。详见 [CLI 使用](cli-run.md)。
