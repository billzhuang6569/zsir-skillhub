---
title: 初始化码创建管理员
description: 使用服务器终端的一次性初始化码创建首个实例管理员。
sidebar: { order: 6 }
---

1. 完成安装，在私人终端查看初始化码；不要转贴包含该码的日志。
2. 打开侧边栏「设置」→「服务与账号」→「自部署服务器」，填入向导输出的 APP 地址，点「测试连接」→「连接到这台服务器」。已登录一探官方也可直接切换，原数据保留，见 [空间切换](../account-and-data/switch-spaces.md)。
3. 未初始化时，检查项显示「尚未初始化，需要创建管理员」；弹窗出现「初始化码」「管理员邮箱」「显示名称」「密码」，底部为「创建管理员并连接」。初始化码原样输入，保留短横线，区分大小写（生成值为四组四个大写字母或数字）；密码长度为 6–128 字符。示例邮箱为 `admin@example.com`，实际填写自己管理的地址。
4. 点「创建管理员并连接」。成功后回到设置，找到「实例管理」→「本实例」→「打开实例管理」；该入口仅管理员可见。

初始化码在 Server 启动后 30 分钟内有效，累计输错 5 次后也须取新码。过期时，在 `deploy/selfhost` 执行：

```sh
docker compose restart server
docker compose logs --since 1m server
```

只重启 Server，不重启 Caddy。创建首个管理员后初始化入口永久关闭；不能靠重启再创建一个。

响应丢失或超时时，等当前请求结束，在连接弹窗点「重新测试」；也可关闭弹窗，回到「服务与账号」对同一地址再点「测试连接」→「连接到这台服务器」。若显示「已初始化」、不再出现初始化码输入框，用刚设置的邮箱和密码点「登录并连接」，不要重复创建。

终端有警告时先对照 [启动日志说明](troubleshooting.md#startup-warnings)，不能仅凭 warning 判定初始化失败。忘记自部署密码时，管理员在相同目录运行：

```sh
docker compose exec server npm run admin -- reset-password --email admin@example.com
```

新密码仅在终端输出一次，登录后立即修改。重置会使旧会话失效；当前没有邮件找回服务。
