迁移把你选择的 Skill 复制到目标账号，原空间的数据保留。CLI `server use` 只切换空间，不执行这里的桌面迁移流程。

## 切换时迁移

连接目标服务器并登录后，APP 会询问如何处理原空间的 Skill。选择「迁移并切换」进入预检；也可以只切换，之后再迁移。

预检显示可迁移、跳过、冲突、超额和待处理增量的数量，以及目标账号的配额。确认内容后开始迁移，APP 切到目标账号，迁移提示会显示进度。

同名冲突有三种处理方式：

- **跳过**：保留目标已有内容，不复制这一项。
- **保留为副本**：填写另一个名称，创建个人副本。
- **确认映射到已有 Skill**：关联预检找到的目标 Skill，不覆盖它的内容。

超出目标配额时，可先跳过部分条目，或处理目标账号的容量后再迁移。

## 迁移范围

自己的 Skill 迁移当前已提交版本及可用头像；原服务器没有可安装内容包的条目会跳过。迁移也会合并标签与快捷访问，不删除目标已有的整理关系。

商店条目仍是当前上架版本时，会从商店重新取得；目标已有同一来源、相同内容的条目时，直接映射，不重复导入。已下架或已非当前版本的条目可作为个人副本迁移；目标已有其他版本时需要处理冲突。团队共享条目会跳过，团队权限与作者身份不会随文件复制转移。

「待处理增量」表示快照之外的修改没有迁移，包括尚未提交的本机编辑。迁移不是实时同步；请回原空间检查并提交这些修改，再按需要重新发起。迁移不复制完整版本历史。

## 可选复制个人钥匙

个人钥匙复制默认不勾选。只有主动启用并选中钥匙后，才会复制对应个人钥匙；遇到目标同名钥匙，可以跳过、改名或明确选择覆盖。团队钥匙不会作为个人钥匙迁移。

钥匙复制在 Skill 落地后进行，以便关联目标 Skill 的使用授权。报告只显示钥匙名称与处理结果，不显示钥匙值。

## 再次发起与续传

已在目标空间时，可从设置的「账号与数据」再次发起迁移，选择来源并登录。来源登录只用于读取迁移内容，确认后仍留在当前目标账号。

迁移中断或暂停后，「有未完成的迁移」提示和报告会显示原因。按提示处理后点击「继续」，APP 会核对已经完成的操作，接着处理剩余内容。取消或放弃不会撤销已经成功导入的条目；完成后需要迁移新变化，请重新发起。

## 查看报告

点击「查看报告」可查看导入、映射、跳过、失败数量，以及逐项结果、头像跳过和个人钥匙处理情况。跳过或失败的条目会显示原因。

不要复制会话文件或数据库身份字段来合并空间。个人钥匙、团队授权与作者权不会因复制 Skill 文件而转移；团队共享内容不能直接当作自己的资产导入。

如果只是向自己的实例导入一份你有权使用的文件，可使用 [普通导入](../guides/import-skill.md)。整个自部署实例搬家则使用 [完整备份恢复](../self-host/backup-restore-upgrade.md)。
