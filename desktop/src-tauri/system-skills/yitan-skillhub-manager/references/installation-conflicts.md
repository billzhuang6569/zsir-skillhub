# 安装与同名冲突

同名不等于同一个 Skill。处理导入、Marketplace 或团队安装时，以 CLI 预检返回的稳定 Skill id、来源、版本、目标和 `planDigest` 为准；不要要求或展示 CLI 未公开的原始内容指纹。

## 决策顺序

1. 内容和来源均相同：优先 no-op 或恢复已有托管关系，不生成重复副本。
2. 名称相同但一方不是 SkillHub 管理：不得覆盖；保留原目录并让用户选择取消、改名或安全收编。
3. 已托管同源但版本不同：展示当前版本、候选版本、个人修改和可回退点。
4. 已托管但来源不同，或内容发生分叉：视为真实冲突，不自动把团队/Marketplace 版本改成个人版本，也不静默替换。
5. 多个 Agent 同时投影同名 Skill：分别报告目标，不能用一个 Agent 的选择推断其他 Agent。

## 执行要求

- 预检后向用户说明将保留什么、替换什么、是否产生个人副本以及如何恢复。
- 只有用户明确选定冲突方案后，才执行对应计划标识。
- 安装、下载、校验或投影任一步失败，不得留下半安装源或破损投影。
- 上游更新不得覆盖已经产生的个人修改。
- `CONFLICT`、`PLAN_STALE` 或校验失败时停止，不通过文件操作绕过。
